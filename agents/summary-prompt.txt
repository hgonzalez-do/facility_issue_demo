── How you run it ───────────────────────────────────────────────────────────

Do this with your own shell and then stop. Do not report back in prose.

Do NOT use action_code: it runs in a separate sandbox that does not receive
this session's environment, so MARS_DATABASE_URL is absent there. Start with
`pip install --quiet "psycopg[binary]"` — the image ships no Postgres client.

Never print or echo MARS_DATABASE_URL; it is a credential.

── 1. Read the numbers ──────────────────────────────────────────────────────

Run one Python script that connects to os.environ["MARS_DATABASE_URL"]
(psycopg) and reads from the `tickets` table:

  - total ticket count
  - count grouped by component, ordered by count descending
  - count grouped by severity
  - count grouped by suggested_owner, ordered by count descending

Print the results. You have SELECT on `tickets` and nothing else — you cannot
read complaint bodies, and you do not need to.

── 2. Write the summary ─────────────────────────────────────────────────────

Compose the summary an operations director would circulate to leadership:
measured, slightly defensive of the team, and entirely serious about what the
data shows. Never acknowledge that the underlying complaints are trivial. Never
make a joke. The comedy is that this document could be read aloud in a real
board meeting without anyone blinking.

Then run a second script that INSERTs one row into `summaries` with
columns: total_tickets, top_components, headcount_ask, narrative.

`top_components` is a JSON string of the top three by volume, exactly:
  [{"component": "Beverages", "count": 12}, ...]

Use parameterised queries. Commit, print the inserted summary id, and stop.

Get that id from `INSERT ... RETURNING id`. You have SELECT on `summaries.id`
and on no other column of that table, which is enough for RETURNING and not
enough to read anything back.

Write exactly one row, and make it the real summary. `summaries` is the table
the dashboard reads on stage — it is not scratch space. Do not insert a test
row, do not probe the table with placeholder values, and do not write a row
you intend to replace. If a statement fails, fix the statement; do not work
around it by writing something you did not mean.
